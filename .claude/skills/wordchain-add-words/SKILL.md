# 단어 추가

## 1. 있는지 확인
`node tools/add-words.js check 단어1 단어2 …` → 있는 단어(어느 목록·뜻)와 없는 단어를 보여 준다.
사용자에게 "이미 있음 / 추가함"을 나눠 보고한다. 오타(예: annouce)는 바른 철자로 확인하고 그렇게 말한다.

## 2. 목록과 표기 정하기
| 목록 | 넣는 단어 | 앱에서 |
|---|---|---|
| `[E]` VOCAB_E | 초등 수준, 기본 기능어(전치사·접속사·대명사), 쉬운 복수형 | 기초 수준부터 출제 |
| `[M]` VOCAB_M | 중학 수준, 직업어, 추상어 | 보통·도전에서 출제 |
| `[WF_E]`/`[WF_M]` | 접미사로 만든 단어 | 같음 |
| `[NUM]` VOCAB_NUM | 기수(one~thousand) | **학생 답으로만**, 컴퓨터는 안 냄(NUMW) |

뜻 표기 규칙 ("단어 뜻 (설명)"):
- 접미사: `singer 가수 (sing+er)`, `happiness 행복 (happy+ness, y→i)`, `argument 논쟁 (argue+ment, e 탈락)`
- 동사의 명사형: `decision 결정 (decide→decision)`
- 불규칙 복수: `teeth 이, 치아 (tooth 복수)`, `knives 칼들 (knife 복수, f→ves)` — 단수형이 없으면 함께 추가
- 묵음 글자: `thumb 엄지손가락 (b 묵음)`
- 비교급·최상급은 반드시 `(big 비교급)` / `(big 최상급)`으로 끝낸다 → 규칙 변화형은 컴퓨터가 안 낸다(앱이 이 표기로 판별). 그 밖의 설명에 "비교급)"으로 끝나는 표기를 쓰지 않는다.
- 비교급과 철자가 같은 단어(cleaner, cooler)는 충돌하므로 넣지 않고 사용자에게 알린다.
- 고유명사·고유형용사(달, 요일, 나라·언어·국적, 행성)는 첫 글자 대문자로 적는다: `September 9월`, `Korean 한국어`, `Mars 화성`. 앱은 소문자로 비교하므로 학생이 소문자로 쳐도 인정되고 화면에는 대문자로 보인다.
- 영어에서 거의 쓰지 않는 외래어(sombrero, fondue 같은 다른 나라 음식·옷 이름)는 넣지 않는다.
- 사용자가 "비슷한 유형도"라고 하면 같은 유형(서수, 접속사, 묵음 글자, 직업 등)을 중학생 수준에서 더 찾아 넣는다.

## 3. 추가
임시 파일(스크래치 폴더)에 적고 `node tools/add-words.js add 파일.txt`:
```
[E]
these 이것들 (this 복수)|those 저것들 (that 복수)
[M]
lawyer 변호사|pharmacist 약사
```
이미 있는 단어는 자동으로 건너뛰고, 문법 오류가 있으면 저장하지 않는다.
컴퓨터가 내지 못하게 하라는 단어는 `[NUM]`처럼 별도 목록 + app.html의 cpuPool 필터가 필요하다.

## 4. 확인
`python build.py` 후 `node tests/accept.js 새단어…` (wordchain-test skill, 소리 없음).
끝 글자로 거의 안 나오는 글자(v, j, q, x)로 시작하는 단어는 '못 해 봄'이 나올 수 있다 — check로 등록만 확인.
커밋은 하지 않는다. 사용자가 "완료배포"라고 하면 wordchain-deploy skill로 배포한다.
